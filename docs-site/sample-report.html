4 recommended security settings are switched off

  • Minor
  • Security
  • Desktop and phone
  • Verified
What happened

Your server does not send 4 standard protective instructions (“security headers”) to browsers: Content-Security-Policy (limits which scripts may run on your pages); X-Content-Type-Options (stops browsers from guessing file types); X-Frame-Options (or CSP frame-ancestors) (stops other sites from showing your app inside a hidden frame); Referrer-Policy (controls how much of your page address is shared with other sites).

Why it matters

They are an extra layer of protection that makes common attacks harder. Nothing is broken today, but they are quick to add.

Steps to reproduce
  1. Open http://127.0.0.1:4173/.
  2. Open the developer tools → Network tab, reload, click the first request and look at “Response Headers”.
Evidence

Where: http://127.0.0.1:4173/

Technical details (4 lines)
Missing: Content-Security-Policy
Missing: X-Content-Type-Options
Missing: X-Frame-Options (or CSP frame-ancestors)
Missing: Referrer-Policy
Fix prompt

Paste this into Lovable, Bolt, Cursor or Claude Code.

Please add these HTTP security headers to every response of my app (via the hosting platform's config file or the server middleware):
- Content-Security-Policy
- X-Content-Type-Options
- X-Frame-Options (or CSP frame-ancestors)
- Referrer-Policy
Use safe defaults: "X-Content-Type-Options: nosniff", "Referrer-Policy: strict-origin-when-cross-origin", "X-Frame-Options: DENY" (or CSP frame-ancestors 'none'), "Strict-Transport-Security: max-age=31536000; includeSubDomains", and a Content-Security-Policy that allows only the sources the app really uses. Make sure the app still works afterwards.
