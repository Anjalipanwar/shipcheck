# ShipCheck v0.1.0: independent pre-announcement audit

- **Date:** 2026-11-17
- **Audited:** `main` at `a5bd315` (code identical to the tags `v0.1.0` and `v0` = `38c5fec`; only `docs/PROGRESS.md` differs) and the published npm package `@anjalipanwar/shipcheck@0.1.0`.
- **How:** read-only. All runs used a throw-away copy in the session scratch folder (no `.env`, no AI key) or the published tarball, and only local test servers. Nothing in the repository, git history, tags, GitHub settings or npm was changed. This file is the only file created in the repository. It is not committed.
- **Second reviewer:** an independent reviewer agent read the full source with the same rules. Its findings were compared with mine. Every finding below says whether I reproduced it myself ("Reproduced"), checked it by reading code ("Confirmed by reading") or could not confirm it ("Unverified"). Where the reviewer saw something I did not, the "Source" column says so.

- **Status (added 2026-11-17, after the fixes):** the four "Fix before announcing" items (A-01 to A-04) and A-05 (action guard), A-06, A-08, A-12 and A-16 are fixed in 0.1.1. Every fix started with a test that reproduced the evidence below, and was then broken on purpose to prove the test catches it. The "Status" column in section 2 says what happened to each finding; the commits are listed in `CHANGELOG.md` and `docs/PROGRESS.md`. The rest of this document is the audit as it was written, before any fix.

---

## 1. Verdict

**Not yet. It is safe and good enough to announce after a short 0.1.1 that fixes the four "Fix before announcing" items (about 1–2 days of work).**

What is solid:

- The build, typecheck and lint are clean, and **all 591 unit tests and 181 real-browser tests pass**.
- No secret was ever committed: I searched all 43 commits, both tags and 9 local dangling commits.
- The npm package holds exactly 7 expected files and nothing sensitive.
- The HTML report is locked down well.
- Deliberately breaking the guard, the backstop, the domain lock, the call limit, the time limit or the ownership question makes tests fail.

What blocks the announcement:

- **Two of the README's promises are not true today.**
  - "It stays on your app": an ordinary HTTP redirect takes the browser to another site, and I reproduced this (A-01).
  - "Passwords … are never written to the report": a password inside an address, for example after a form sends its data in the address, is not hidden (A-02).
- **Two robustness bugs cost a user a whole run with no report:**
  - a test password that is an everyday word such as `test` or `check` crashes the run at the very end (A-03);
  - a heavy page makes the run ignore `--max-minutes` and hang (A-04).

None of the four is hard to fix. Because the package is already public, the safest order is: fix → publish 0.1.1 → move `v0` → announce.
